# OnePiece 简历项目草稿

> 数据位暂时保留为占位符，只有在两套正式产物完成、逐行对齐和 SHA-256 验收后填入。

## 项目名

**TencentGR-1M 大规模生成式序列推荐复现与架构对照**

## 三条版

- 基于 2025 腾讯广告算法大赛 TencentGR-1M 与 OnePiece，搭建 HSTU +
  sample-bias-corrected InfoNCE 训练和 66 万候选精确 Top-10 检索链路；在 1,001,845
  用户、4,783,154 Item 索引上完成资源缩放复现，离线 HR@10 / NDCG@10 / 综合分为
  `待填 / 待填 / 待填`。
- 设计 HSTU 4×128 vs. 因果 Transformer 4×128 的严格单变量对照，固定 90/10 用户
  划分、78,921 条最后点击留出、训练目标、优化器、6 Epoch 和候选池；用逐用户配对
  区间与历史长度切片分析架构差异 `待填`，并明确单 seed 与资源缩放的结论边界。
- 建立共享 H200 上的可恢复实验与产物治理：双卡隔离运行、原子断点、状态心跳、
  SHA-256 下载校验、预测行对齐、远端及时清理，以及 Hugging Face Pro 私有大产物 / 
  GitHub 公共代码文档分仓发布。

## 面试开场版

我没有只跑官方 Baseline，而是选择了获许可复现的 OnePiece，把它的核心 HSTU 与
InfoNCE 路线缩放到共享 H200 可承受的 4×128 配置。为了回答“提升来自架构还是训练
与评测变化”，我冻结了 78,921 个用户和 66 万候选的无泄漏离线协议，再跑一条除
编码器外完全相同的 Transformer 对照。最终我不仅报告 HR@10 和 NDCG@10，也检查
逐行对齐、历史长度切片、训练曲线、参数/显存/吞吐，并把单 seed、冷启动候选和非
官方榜单这些限制写进结论。项目的另一半是工程可信度：每次输出都先下载验哈希，再
清共享盘；大权重进私有 HF，公开 GitHub 只放可复现代码和可辩护的结果。
