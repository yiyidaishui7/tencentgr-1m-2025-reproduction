# 技术面试深挖问答

## 项目与评测

### 1. 你到底复现了什么？

我复现并工程化了 TencentGR-1M 的 SASRec 风格全模态序列推荐链路，包括训练、Item 候选编码、用户 Query 编码、精确内积 Top-10 和可审计离线评估。目标不是复刻官方榜单名次，而是得到可重复、可解释的端到端实验。

### 2. 为什么不能称为官方比赛成绩？

官方隐藏测试标签和评测服务不在本地离线协议中。我的分数来自固定 seed 的最后点击留出，因此只称为“比赛风格综合分”，不称为榜单分数或名次。

### 3. 如何避免目标泄漏？

对验证用户找到最后一次有效点击，把该 Item 作为 Target；Query 序列只使用它之前的事件。实现和测试都会拒绝把目标位置包含进历史。

### 4. 为什么最终是 78,921 个用户，而不是全部验证用户？

100,184 名验证用户中，1,745 人没有有效点击，19,518 人的目标不在官方候选集合，因此剩余 78,921 人进入可比较的 Top-10 评测。代码同时输出这些排除计数，避免只报告最终样本量。

### 5. HR@10 和 NDCG@10 分别说明什么？

HR@10 只关心目标是否进入前十；NDCG@10 还根据目标排名折损，目标越靠前贡献越大。本项目综合分为 `0.31 * HR@10 + 0.69 * NDCG@10`。

### 6. 为什么候选集合不是全部 478 万 Item？

评测遵循数据集提供的约 66 万候选集合。Item 索引空间和评测候选池是不同概念；把二者混为一谈会错误改变难度和分数。

## 模型与训练

### 7. 模型结构是什么？

Item/User ID、稀疏特征、数组特征和可选多模态向量先映射到统一隐藏空间，再输入带位置编码和因果 Mask 的 SASRec 风格 Transformer。默认隐藏维度 32、1 层、1 个 Head，最后有效位置作为用户查询表示。

### 8. 多模态特征如何融合？

字段 81 的 32 维向量通过线性层变换到隐藏维度，与 Item ID 和其他 Item 特征拼接，经过 Item DNN 压回 32 维。no-MM 消融只移除这条向量输入，不改变其他特征和模型容量配置。

### 9. 训练目标是什么？

每个有效序列位置构造下一 Item 正样本和采样负样本，分别计算 BCEWithLogitsLoss，再将正负损失相加。Adam 学习率 0.001，3 个 Epoch，固定 seed 2025。

### 10. 为什么比较 maxlen 101 和 50？

历史 81+ 是最大且表现最差的分桶。`maxlen=50` 用来测试更强的近期偏置是否减少长历史噪声。2×2 设计同时保留 MM/no-MM 两条线，避免把窗口效应误判成多模态效应。结果中 no-MM50 为最佳点估计；81+ 组相对 no-MM101 提高 12.96%，但短历史桶并未普遍受益。

## 实验可信度

### 11. no-MM 分数更高，是否说明多模态没用？

不能。no-MM101 相对 MM101 的区间跨 0；no-MM50 相对 MM50 的固定评测人口区间虽然为正，但每个配置只训练一个 seed，训练随机性没有被估计，而且整体 2×2 交互区间仍跨 0。可辩护结论是“当前固定 seed 下，no-MM50 是最佳点估计，当前直接融合没有展示可跨 seed 推广的收益”，而不是“多模态没用”。

### 12. 为什么做逐行配对而不是只比较两个总分？

逐行配对确认两个模型面对的是同一用户、同一 Target 和同一历史长度，并能统计“仅A命中、仅B命中”等转移。这样既能发现数据错位，也能对每个用户的指标差计算区间。

### 13. 如何保证四组实验只改变目标变量？

固定 seed、数据划分、候选池、优化器、Batch Size、Epoch、隐藏维度和评测代码；配置表只改变 `maxlen` 与 `disable_mm_emb`。每组产物使用同样的哈希与行对齐验收。

### 14. 为什么用精确检索而不是 Faiss ANN？

消融阶段需要一个不含近似误差的正确性基线。精确矩阵内积可以隔离模型差异。生产化时可以引入 ANN，但应以精确结果测量 Recall 与延迟权衡。

## 工程化

### 15. 从官方 Baseline 改了什么？

移除硬编码路径和设备；支持 CPU、CUDA 和 Ascend；增加固定 seed、断点恢复、候选 Schema/ID 审计、无泄漏离线评估、精确 Top-K、no-MM 开关、SafeTensors 发布、SHA-256 同步清理及回归测试。

### 16. 如何处理 NPU 与 H200/CUDA 的差异？

设备选择集中到运行时适配层，模型和数据协议保持一致。不同后端不能保证逐位相同，但可以保证输入、结构、训练超参和评测契约一致；因此项目声称方法级复现，而不是 bitwise reproduction。

### 17. 权重下载失败时怎么处理？

首次把约 1 GB 权重切成 16 片并行 SCP，11 片成功、5 路连接失败。恢复方案先校验已有分片哈希，只补缺失部分，并把最大并发降至 8；重组后再校验整文件 SHA-256，成功后才清理远端。

### 18. 如何避免共享机器泄露项目？

远端使用权限 700/600 的私有目录和通用脚本名，参数通过私有配置/标准输入进入进程；不读取其他用户任务信息，不抢占进程，并保留至少一张共享 GPU 空闲。

### 19. 如何管理大产物？

小型代码和指标公开；受限数据、PyTorch 权重和完整日志进入私有归档；公开模型使用 SafeTensors。所有上传和下载都有清单与 SHA-256，远端输出在本地验证后立即清理。

### 20. 如果继续优化，优先做什么？

先完成多 seed 验证，确认窗口/融合差异是否超过噪声；再尝试门控多模态融合、特征归一化、按历史长度自适应窗口，以及用精确检索基线评估 ANN 加速。

### 21. 固定 seed 是否意味着任何机器都能逐位复现？

不意味着。项目固定 Python、NumPy、PyTorch、用户划分以及训练/验证 DataLoader 的生成器，并设置 cuDNN deterministic、关闭 benchmark，从而控制主要随机来源；但不同 PyTorch/CUDA/cuDNN 版本、GPU 架构和个别算子仍可能产生数值差异。因此这里承诺的是配置、数据划分、评测人口和方法级可复现，具体已产出的文件用 SHA-256 保证身份，不声称跨环境 bitwise reproduction。

### 22. 约 7.9 万查询乘 66 万候选，精确检索为什么不会直接爆显存？

实现会把约 66 万个 32 维候选向量常驻设备，但查询按 Batch 分块。正式评测的检索 Batch 为 2,048，因此一次只生成约 `2048 × 660k` 的分数矩阵，取完 Top-10 后立刻释放该批中间结果，而不会物化完整的 `78,921 × 660k` 矩阵。代价是计算量仍大，所以它适合作为消融正确性基线；线上应使用 ANN，并相对这个精确结果评估召回损失。

### 23. 负样本是怎样采的，有什么局限？

每个有效的下一 Item 位置采一个随机负 Item；负 Item 必须存在特征，并排除该用户序列中出现过的 Item。这个方案简单且与官方 Baseline 接近，但随机负样本通常偏容易，而且训练时的全 Item 采样分布与评测候选池并不完全相同。后续可以比较候选池内采样、流行度校正、in-batch negative 或 hard negative，同时保持评测协议不变。

### 24. 为什么公开两个权重，面试时应该展示哪个？

`model.safetensors` 是最初完成端到端审计的 MM101 基线，适合说明官方 Baseline 的可复现链路；`model_nomm50.safetensors` 是 2×2 中最佳固定 seed 点估计，适合演示最终实验结论。后者只有 46 个张量，因为构造模型时关闭了多模态入口，加载时必须同时设置 `--maxlen 50 --disable_mm_emb`；不能把它塞进 MM101 结构。简历数字展示 no-MM50，但同时保留 MM101 是为了让“基线—消融—最佳配置”的证据链完整。

### 25. 这个项目需要多少显存和运行时间？

66 万个 32 维 FP32 候选向量约 80.6 MiB；检索 Batch 为 2,048 时，主要单批分数矩阵约 5.04 GiB。实现不会物化完整的 7.9 万乘 66 万矩阵，因此 24 GB 级单卡可以运行。四组正式离线评测在一张 H200 上各约 134–242 秒，但这是包含数据构造、候选/Query 编码、精确 Top-10 和指标计算的单次端到端记录，不是线上延迟 Benchmark。
