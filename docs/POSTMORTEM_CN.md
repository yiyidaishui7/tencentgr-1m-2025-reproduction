# 工程故障与权衡复盘

## 1. 环境和路径耦合

**现象：** 官方 Baseline 包含机器相关路径和设备假设，无法直接在不同后端运行。

**处理：** 把数据、输出和设备变成显式参数；增加 CPU/CUDA/Ascend 路由与小规模 smoke test。

**经验：** “代码能启动”不等于可复现。输入契约、随机种子、设备语义和输出清单都需要显式化。

## 2. 候选与 Item ID 对齐

**风险：** 序列、Item 特征、多模态文件和候选 Parquet 可能使用不同字段名或 ID 表示，静默错位会让模型正常运行但指标失真。

**处理：** 建立 canonical ID、兼容公开/旧 Schema，并在评测前输出缺失与排除人口。

**经验：** 推荐系统中，ID 对齐往往比模型公式更容易造成灾难性错误。

## 3. 共享 GPU 调度

**约束：** 任务只使用一张卡；优先 GPU0–5；只有当 GPU6/7 同时连续空闲 15 分钟时才允许使用 GPU6，并始终保留 GPU7。

**处理：** 启动器只读取 GPU 索引、显存和利用率，不读取其他用户任务内容；自动等待并选择第一张合规空闲卡。

**经验：** 共享资源策略应编码进启动器，而不是依赖人工记忆。

## 4. 本地 watcher 停滞

**现象：** 远端 MM50 完成后 watcher 曾停止推进；no-MM50 评测完成时，本地 watcher 进程仍存活但状态长期不刷新，且没有 SSH/SCP 子进程。

**处理：** 验证远端任务已完成、结果完整且 GPU 已释放后，只终止本任务假活的本地 watcher，再启动新的同步控制器附着到 `complete` 状态；没有重训、重复评测或触碰其他进程。

**经验：** 训练状态和产物同步状态必须分离；“进程存在”不等于“进度活跃”，恢复同步也不应触发训练重跑。

## 5. 并行权重下载部分失败

**现象：** 约 1.04 GB 权重的 16 路 SCP 中，11 片完成、5 路失败；旧错误处理还因安静模式丢失了具体连接信息。

**处理：** 远端保留完整权重；本地对已有分片逐片校验 SHA-256，只补传缺失/损坏分片，并把并发上限降到 8。重组权重通过整文件 SHA-256 后才清理远端。

**经验：** 并发传输必须具备分片清单、幂等恢复和端到端哈希；“提高并发”不是无代价优化。

## 6. 实验结论边界

**现象：** 历史 Baseline 2×2 中 no-MM50 是最高点估计，且部分固定人口配对区间为正，一度容易被过度表述成窗口或多模态效应。

**处理：** 先对四组 78,921 行预测做用户、Target 和历史长度对齐；后续源码审计又发现训练会重复插入 user token，而评测只插入一次，且重复数量随序列长度和 `maxlen` 变化。因此旧分数保留作历史产物，窗口与多模态解释全部撤回，等待修复后四组重训。

**经验：** 简历中的克制结论比夸大的单次分数更经得住面试追问。

## 7. 训练与评测 user-token 契约不一致

**现象：** `new_load_user_data` 的每个事件记录都携带用户 ID。训练集曾按“用户 ID 非零”插入 user token，N 个事件会产生 N+1 个 user token；推理与最后点击评测按每条序列构造一个 user ID token。

**影响：** 正负标签数量没有直接增加，但因果注意力的上下文、绝对位置和用户特征承载位置发生变化。`maxlen=50/101` 还会保留不同数量的重复 token，使历史 2×2 不再是预期的单变量设计。

**处理：** 训练构造改为只在 `user_feat is not None` 的用户记录上插入 token，空特征字典仍保留 user ID；`MyTestDataset` 同步修复为保留空特征的用户与 Item。回归测试覆盖非空/空用户特征、无特征 Item 与窗口边界。旧 checkpoint 与指标不覆盖，新协议重训后另行版本化发布。

**经验：** 哈希只能证明产物身份，不能证明数据契约正确。源码级契约测试必须覆盖训练与评测两端。
