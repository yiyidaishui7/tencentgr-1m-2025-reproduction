# 项目白话说明：先讲懂，再讲细

这份材料面向第一次了解项目的人，也可以当作面试前的复习提纲。[PPT](INTERVIEW_DECK_CN.md) 负责展示，[讲稿](INTERVIEW_SCRIPTS_CN.md) 负责口述，技术细节和完整结果放在文末链接中。

## 1. 一句话说清项目

看用户过去的行为，预测他下一次会点击什么；在固定的评测规则下，比较不同模型，并排查一次加了新方法却变差的实验。

这是基于腾讯官方 Baseline 和公开 OnePiece 方法的独立离线复现。主要结果来自全候选向量排序，另外做了 SID 编号预测与生成候选实验，不是文本生成应用，也不是官方比赛排名。

## 2. 输入是什么，输出是什么？

输入包括用户按时间排列的点击、曝光等历史记录，以及推荐对象的 ID 和属性。模型输出候选对象的匹配分数，最后取最高的 10 个。

可以用一个只为说明流程的例子理解：历史是“看过 A、点过 B、看过 C”，真正的下一次点击是 D。评测时把 D 留作答案，模型只看 D 之前的记录，判断能不能把 D 放进前 10。A、B、C、D 是示意符号，不是实际用户记录。

三个规模要分清：

| 数字 | 它表示什么 |
|---|---|
| 1,001,845 个用户 | 原始数据的用户规模，PPT 简写为 100 万。 |
| 4,783,154 个对象索引 | 数据中的 Item 索引空间，PPT 简写为 478 万。 |
| 660,000 个候选 | 历史评测实际从中选择推荐结果的对象池。 |

验证集最初有 100,184 人。去掉 1,745 名没有有效点击的用户，以及 19,518 名答案不在候选池中的用户，最后评测 78,921 人。不同模型使用相同的这批人，且答案和历史逐行对应。

## 3. 模型怎样给对象打分？

用户侧把历史记录变成一组表示兴趣的数字；对象侧把 ID 和属性变成另一组数字。这组数字叫向量。两组归一化向量做内积，得到匹配分数，再按分数排序。

这里的“向量”是模型学出来的表示，不要把某一维直接说成“价格”“颜色”等人工含义。

| 名词 | 用简单语言解释 | 技术追问时补充 |
|---|---|---|
| Embedding / 向量 | 用一组数字表示一个对象，方便模型计算关系。 | ID 和稀疏特征经过模型编码。 |
| 用户侧 / User Tower | 读用户过去的记录，概括当前兴趣。 | 使用行为序列编码器得到 Query。 |
| 对象侧 / Item Tower | 把候选对象变成可比较的数字表示。 | 本轮 OnePiece 主实验使用 ID 和稀疏属性，不把基础链路的可选多模态说成这一轮都用了。 |
| HSTU | 给历史记录分配权重，再控制保留多少信息。 | U/Q/K/V 联合投影、SiLU 权重、相对位置偏置与 U 门控。 |
| InfoNCE | 要求正确的下一条，得分高于同一批里的其他对象。 | 批内对比学习；其他有效下一条构成负例来源。 |
| LogQ | 校正热门对象在训练中更常被抽到的偏差。 | 频率来自训练数据，校正的是采样偏差，不等于直接承诺改善公平性。 |
| 4×128 | 模型有 4 层，表示向量的维度是 128。 | 8×512 同时改变了层数和维度。 |
| Epoch / 一轮 | 按配置把训练数据走一遍。 | 这里的架构和容量对照训练 6 轮。 |
| Seed / 随机种子 | 给随机过程一个固定起点，便于重复实验。 | 换种子重新训练，结果仍可能变化。 |

## 4. 怎样知道推荐得好不好？

HR@10 看“答案有没有进前 10”。NDCG@10 还看“答案排得够不够靠前”。一个答案排第 1 和排第 10，HR 都算命中，但第 1 的 NDCG 更高。

项目综合分为 `0.31 × HR@10 + 0.69 × NDCG@10`。HSTU 8×512 的 HR@10 为 12.08%，可以近似说成“每 100 名评测用户，约 12 人的真实下一条进入前 10”。这不是线上点击率。

评测每批处理 128 个用户，遍历全部 66 万候选，只保留前 10。这样不用一次存下整个 `78,921 × 660,000` 分数矩阵。这里选择精确计算，是为了先避免把近似检索误差混入模型对照；还没有把这些结果当作线上速度基准。

## 5. 做了哪几组实验，分别回答什么？

| 问题 | 实验 | 得到的结论 |
|---|---|---|
| 同样大小，换历史处理模块有帮助吗？ | 4×128 Transformer 对照 4×128 HSTU；其余条件保持一致。 | 综合分 0.06373 → 0.06634，相对 +4.10%。这是单次训练的结构对照。 |
| 扩大模型，在这组数据上有帮助吗？ | HSTU 4×128 → 8×256 → 8×512。 | 综合分 0.06634 → 0.07608 → 0.08335；最大相对最小 +25.63%，资源开销同时增加。 |
| 加上语义编号预测有帮助吗？ | 无 SID、旧 SID、新 SID 0.02 / 0.05。 | 旧版明显下降；修改后接近无 SID，还没有证明稳定额外收益。 |
| 更换评分规则会影响分数吗？ | 同一已保存模型，更换候选与历史过滤规则。 | 0.08335 → 0.08552，+2.61% 来自评测规则变化，不是重新训练的收益。 |

这些实验不能互相替代。换结构、增加容量、修改辅助任务和修改评测规则，是四种不同的变化。

百分比按未四舍五入的分数计算。例如 +4.10% 是 `(HSTU 分数 − Transformer 分数) / Transformer 分数`，不是综合分增加了 4.10 个百分点。

## 6. SID 为什么值得讲？

SID 可以理解成一个对象的一组短编号。本项目把已训练对象向量压成两个数字，再让模型额外学习预测这两个数字。示意上，如果 A 和 B 都得到同样的 `[12, 8]`，仅凭这个编号就不能区分它们；该编号例子只用于解释。

第一轮的情况是：

- 4,783,154 个对象，只有 2,533,113 组不同编号。
- 相减得到 2,250,041 个重复占用；不是两两冲突配对数。
- 两个辅助损失等权加入，总损失先降后升。
- 全候选排序综合分从 0.0833458 降到 0.0784571，相对下降 5.87%。

调整包括重新分配重复编号、把辅助权重改为 0.02 / 0.05，以及第一轮从 0 逐渐增加权重。最后一项就是 warm-up，可以说成“慢慢加大辅助任务的训练强度”。

| 版本 | 综合分 | 相对无 SID |
|---|---:|---:|
| 无 SID | 0.0833458 | 对照 |
| 旧 SID | 0.0784571 | −5.87% |
| 修改后，权重 0.02 | 0.0834596 | +0.14% |
| 修改后，权重 0.05 | 0.0827533 | −0.71% |

0.02 版与无 SID 的逐用户配对差值区间约为 `[-0.00079, +0.00102]`，包含 0。可以说“明显下降已修复，得分接近原水平”，还不能说已经证明稳定提升，也不能说已经证明两者严格等价。编号、权重和预热是一起调整的，不能单独归因。

这部分的价值是完整展示一次失败排查：发现下降，核对编号和日志，提出修改，重新比较，保留没有证明的部分。当前零碰撞映射是全局残差近似，存在跨第一层编码的重分配，不等于上游严格层级方案；映射生成脚本目前不在公开仓库。

## 7. 面试怎样说自己的贡献？

建议按三件事说，实际使用时只保留自己确实承担的内容：

1. 让实验跑起来：整理路径和设备配置，复现训练与评测，支持断点恢复。
2. 让结果能比较：固定用户、答案、候选和评分规则，分别设计结构、容量、SID 对照。
3. 让结论查得到：核对 ID、逐行预测和文件校验值，把代码、配置、指标和说明整理到对应入口。

口述可以用：“方法来自公开方案，我负责复现、扩展实验和排查问题。最能代表我的工作的是把结果和产生结果的过程一起核对清楚。”

需要保留的边界是：离线复现而非官方排名；每个训练配置只有一个种子；更换评测规则的涨分不计作模型提升；基础 Baseline 的历史 maxlen/MM 2×2 在数据构造修复后仍待复跑。
