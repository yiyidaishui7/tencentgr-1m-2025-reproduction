# 面试展示讲稿：简单语言版

对应 [3 页信息增强版 PPT](INTERVIEW_DECK_CN.md)。三页都是内容页，分别讲“做什么、怎么做、出了问题怎么办”。PPT 备注区已放入详细讲稿和证据来源。时间为建议值，先试讲一遍，再按自己的语速删减。

第一次准备建议先读 [项目白话说明](PROJECT_EXPLAINED_CN.md)，再练下面的 3 分钟版。页面上的数据供面试官追问，不需要全部念出来。

## 30 秒开场

这个项目用用户过去的行为，预测他下一次会点击什么。我在约 100 万用户的数据上复现推荐模型，固定评测规则后，分别比较模型结构和模型大小。HSTU 在同规模对照中提高了 4.10%，扩大模型后又比小配置提高了 25.63%。我还排查了一次加入语义 ID 后的下降，把重复编号和辅助训练方式一起调整，结果恢复到接近原水平。目前这些都是单次训练的离线结果。

## 3 分钟逐页版

### 第 1 页：任务与评测，约 55 秒

“这个项目想解决一个直接的问题：看一个人过去的行为，预测他下一次会点什么。

数据约有 100 万用户和 478 万个对象索引，评测时从官方给定的 66 万候选中选出前 10 个。我的做法是把验证用户的最后一次点击留作答案，只把答案之前的记录交给模型。排除无法评测的用户后，固定评测 78,921 人。

模型把用户兴趣和候选对象都变成数字向量，再计算它们有多匹配。HR@10 看答案有没有进前 10，NDCG@10 还看答案排得有多靠前。所有模型用同一批用户、同一套候选和过滤规则，分数才能直接比较。”

转场：“规则固定后，我再比较换模型和扩大模型有没有帮助。”

### 第 2 页：方法与结果，约 60 秒

“这里有三个核心名词。HSTU 负责读历史、分配权重；InfoNCE 要求真实下一条的得分高于同一批中的其他对象；LogQ 则按训练频率校正热门对象更常被抽到的偏差。

我先保持 4 层、128 维和其他训练条件一致，只替换处理历史的模块。HSTU 综合分是 0.06634，Transformer 是 0.06373，相对提高 4.10%。

然后把 HSTU 扩大到 8 层、512 维，分数达到 0.08335，比小配置提高 25.63%。资源消耗也增加了：记录中的训练时间从约 79 分钟增加到 181 分钟，显存峰值从 9.23 GiB 增加到 26.16 GiB。这里同时加深、加宽，而且每个配置只训练了一次，所以不能拆分各自贡献，也还需要多次训练验证。”

转场：“接下来，我在较大的模型上试了一个额外任务：预测对象的语义编号。”

### 第 3 页：SID 排查与修复，约 65 秒

“SID 可以理解成对象的一组短编号。模型除了学习推荐下一条，还要学习预测这个编号。

第一轮加入后，综合分下降 5.87%。排查发现多个对象用了同一组编号，重复占用数约 225 万；辅助任务也被等权加入，总损失出现先降后升。这些是排查线索，不能单独证明每一项造成了多少下降。

我重新分配编号，把重复占用数降到 0，再比较 0.02 和 0.05 两档辅助权重，并在第一轮逐渐增加权重。0.02 版恢复到 0.08346，只比原模型高 0.14%，差异区间仍包含 0。因此我的结论是明显下降已修复、得分接近原水平，尚未证明稳定提升。

另外，同一个模型只更换评测过滤规则，分数就高了 2.61%。这也提醒我，模型的变化和评分规则的变化需要分开解释。”

收尾：“我最想展示的是：能把模型跑通，能做公平对照，也能把失败原因的线索和真正验证的结论分清楚。”

## 6–8 分钟详细版

### 第 1 页：约 2 分钟

“这个项目的输入是用户过去的点击、曝光等记录，以及推荐对象的 ID 和属性。输出不是一段文字，而是一组推荐对象，最后取分数最高的 10 个。

原始数据有 1,001,845 个用户、4,783,154 个对象索引。478 万是索引空间，正式评测使用的是其中官方给定的 660,000 个候选。固定随机种子 2025，按用户做 90/10 划分，验证集有 100,184 人。

我把每个验证用户的最后一次有效点击留作答案，只使用答案之前的历史。1,745 人没有有效点击，19,518 人的答案不在候选池中，排除后得到 78,921 人。不同模型必须使用相同的用户、答案和历史长度，不能某个模型测了一批更容易的用户。

模型可以分成两边。用户侧用 HSTU 读取历史，得到一组表示兴趣的数字；对象侧把 ID 和稀疏属性变成另一组数字。两组归一化向量做内积，得到匹配分数。

评测时每批处理 128 个用户，和全部 66 万候选算分，算完立刻保留前 10。这样能得到精确结果，又不用一次存下所有用户和所有候选的完整分数矩阵。

HR@10 是答案进入前 10 的用户比例。8×512 模型是 12.08%，大致相当于每 100 个评测用户，约 12 人的真实下一条出现在前 10。NDCG@10 还会奖励更靠前的名次。最后按 0.31 和 0.69 加权得到综合分，这不是点击率，也不是线上业务收益。

我的工作重点是训练复现、对照实验、错误排查和结果核验。模型方法参考腾讯官方 Baseline 和公开 OnePiece，我会保留来源，把自己的工作说成复现、扩展和验证。”

### 第 2 页：约 2 分钟

“先解释方法。HSTU 是处理行为序列的模块。可以把它理解为：根据记录之间的关系和位置分配权重，再用类似控制开关的门控决定保留多少信息。和它对照的 Transformer 也读同样的历史，但内部计算方式不同。

InfoNCE 是训练要求：对一段历史，真实的下一条是正确对象，同一批中的其他对象作为对照，让正确对象得分更高。LogQ 则根据训练频率处理抽样偏差。热门对象更容易在训练中出现，需要校正这种出现机会的不同；这不等于简单地压低所有热门推荐。

第一个实验只换历史编码器。两边都是 4 层、128 维，批大小 32，训练 6 轮，其他特征、优化器、随机种子和评测条件一致。HSTU 得分 0.0663408，Transformer 得分 0.0637291，相对提高 4.10%。这回答了在当前固定条件下，结构替换是否有效。

第二个实验扩大 HSTU。4×128、8×256、8×512 的分数分别是 0.06634、0.07608 和 0.08335，最大配置比最小配置提高 25.63%。但同时增加了层数和向量维度，所以我只说整体扩容有效，不分别认领深度或宽度的贡献。

效果之外也要看成本。HSTU 的训练记录从 78.6 分钟增加到 180.8 分钟，显存峰值从 9.23 GiB 增加到 26.16 GiB。这些是对应实验的资源记录，不是线上延迟，也不适合直接拿来比较不同硬件。

最后，每个配置只有一个训练随机种子。逐用户统计能描述当前两个固定模型在这些用户上的差异，却不能说明换一个初始化重新训练仍然一定提高。下一步需要多次训练。”

### 第 3 页：约 2–3 分钟

“SID 是语义 ID。这里从已经训练好的对象向量出发，用两级残差聚类，每级有 4,096 个编码，把一个对象压成两个数字的编号。模型再增加一个学习目标：预测这两个数字。它和主推荐任务一起训练，但两者不一定同时变好。

第一轮排序分数从无 SID 的 0.0833458 降到 0.0784571，下降 5.87%。我检查了编号映射和训练日志。4,783,154 个对象只有 2,533,113 个不同编号组合，两者相减是 2,250,041，表示多出的对象占用了已有编号，不是两两冲突的配对数。两个辅助损失被等权加入，总损失从第三轮约 24.91 反弹到 42–44。这些现象提示编号和训练强度都值得排查。

我做了三类调整：重新分配重复编号；把辅助任务权重设为 0.02 或 0.05；第一轮从 0 逐步增加到设定权重。这样可以在主任务之外，以较小且逐渐增加的强度加入辅助任务。

结果是 0.02 版得分 0.0834596，比无 SID 高 0.14%；0.05 版为 0.0827533，低 0.71%。0.02 的逐用户配对差值区间约为 -0.00079 到 +0.00102，包含 0。因此我可以说退化被修复、得分接近原水平，不能说已经证明有额外收益，也不能把区间含 0 说成证明了严格等价。

旧版到新版同时改了编号、权重和预热，不能把恢复归因于某一项单独修改。0.02 和 0.05 两个新版之间，才是在其余条件固定时比较权重。当前映射使用全局残差近似，也不是严格复现上游层级 SID。

还有一项评测检查：同一个已保存模型，更换候选和历史过滤规则后，得分从 0.0833458 变成 0.0855212，高了 2.61%。模型没有重新训练，因此这是评测规则的影响，不能计入模型优化收益。

项目的收获是把训练、对照、失败排查和结果核验连起来。后续优先做多个随机种子，并分别验证编号、权重和预热的独立影响。”

## 面试官打断时，先用一句话回答

| 追问 | 先回答这一句 | 再展开 |
|---|---|---|
| 你个人做了什么？ | 我把上游方案复现成能运行、能比较、能核对结果的实验流程。 | 数据与评测固定、模型对照、SID 排查、断点和文件校验。 |
| HSTU 是什么？ | 它是一个处理历史行为的模块，负责给记录分配权重并控制保留的信息。 | 联合 U/Q/K/V 投影、SiLU 权重、相对位置和门控。 |
| 为什么不用近似检索？ | 先得到精确答案，模型差异才不会混入检索近似误差。 | 分批计算降低内存压力，后续再测近似检索的召回与延迟。 |
| 生成式推荐体现在哪里？ | 本轮主要结果来自向量排序，另有预测 SID 编号并生成候选的实验。 | 不把它说成文本生成，也不说已用生成路径替代全候选排序。 |
| SID 最后提升了吗？ | 明显下降已修复，但还没有证明稳定提升。 | 0.02 版仅高 0.14%，配对差值区间包含 0。 |
| 225 万碰撞怎么算？ | 对象总数减去不同编号组合数。 | 4,783,154 − 2,533,113 = 2,250,041，不是两两冲突数。 |
| 4.10% 是什么提升？ | 综合分的相对提升，不是增加了 4.10 个百分点。 | 用未四舍五入的综合分计算差值，再除以 Transformer 的分数。 |
| 为什么不直接说模型更大就更好？ | 这里只验证了这三档配置和当前数据、预算。 | 更大配置没有测试，层数和维度也没有分别控制。 |
| 有什么没做完？ | 多次训练的稳定性、各项 SID 修改的独立影响还需要补实验。 | 映射生成脚本未公开；基础 Baseline 的历史 2×2 修复后待复跑。 |
