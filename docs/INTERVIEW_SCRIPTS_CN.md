# 面试讲稿

## 3 分钟版本

这个项目是对 2025 腾讯广告算法大赛 TencentGR-1M Baseline 的端到端复现与工程化。原始代码的主要问题不是模型公式，而是与特定设备、路径和评测环境绑定，缺少一套可以审计的离线闭环。所以我的目标是把它改造成一个在不同设备上都能训练、能给出可信 Top-10 指标、并且所有结果都能追溯到权重和日志的系统。

模型采用 SASRec 风格的因果 Transformer。用户和 Item ID、稀疏/数组特征以及字段 81 的多模态向量先映射到 32 维隐藏空间，再经过一层自注意力。训练用正负 BCE；推理时分别编码约 66 万候选 Item 和验证用户的历史序列，再做精确内积 Top-10。

评测上我实现了固定 seed 2025 的 90/10 用户划分。对每个验证用户留出最后一次点击，Query 中只使用目标之前的历史，避免泄漏。100,184 名验证用户中，排除无点击和目标不在候选池的用户后，最终评测 78,921 人。多模态基线的 HR@10 是 0.03135、NDCG@10 是 0.01597、综合分是 0.02074。

我还做了 maxlen 101/50 × MM/no-MM 的逐行对齐 2×2 实验。no-MM50 的综合分 0.02232，是最佳固定 seed 点估计，相对 MM101 提高 7.65%。在 no-MM 条件下短窗口提高 5.08%，在 maxlen50 下关闭多模态提高 6.20%；但整体交互项区间跨过 0，而且每组只有一个训练 seed，所以我不声称存在稳定协同，也不说多模态无效。进一步切片发现，81+ 历史用户占 63.47%，no-MM50 在该组相对 no-MM101 提高 12.96%，总体收益主要由长历史组驱动。

工程上，我增加了 CPU/CUDA/Ascend 设备适配、ID 对齐审计、精确 Top-K 后端、断点恢复、SHA-256 验证和公开/私有分仓发布。遇到 1 GB 权重并行下载部分失败时，我保留已完成分片、逐片校验并只补传缺失部分，最后通过整文件哈希后才清理远端。这一项目让我认识到，推荐系统的评测契约、ID 对齐和产物治理，往往和模型本身一样重要。

## 10 分钟版本

### 0:00–1:00：问题和目标

- 官方 Baseline 提供了模型入口，但环境耦合强，缺少完整可审计的离线评测。
- 项目目标：完成数据到 Top-10 的方法级复现，并建立可重复、可解释、可发布的证据链。
- 明确边界：离线复现，不声称官方榜单成绩。

### 1:00–2:30：数据与 ID 对齐

- 1,001,845 用户、4,783,154 Item 索引空间和约 66 万候选池是三个不同概念。
- 序列、特征、多模态和候选文件可能使用不同 Schema/ID 表示。
- 通过 canonical ID 与 Schema 兼容层审计映射，并显式统计排除人口。

### 2:30–4:00：模型与训练

- SASRec 风格因果 Transformer：hidden 32、1 Block、1 Head、Dropout 0.2。
- ID、稀疏、数组和多模态向量投影后融合。
- Batch 2048、Adam 0.001、3 Epoch、seed 2025；下一 Item 正负 BCE。
- no-MM 只关闭多模态入口，保证消融仍是单变量实验。

### 4:00–5:30：离线评测协议

- 固定 seed 的 90/10 用户划分。
- 最后点击作为 Target，严格更早的历史作为 Query。
- 100,184 验证用户最终得到 78,921 个合格样本。
- 精确内积 Top-10 隔离 ANN 误差；综合分为 `0.31 HR + 0.69 NDCG`。

### 5:30–7:00：结果与统计纪律

- 四组综合分：MM101 0.02074、no-MM101 0.02124、MM50 0.02102、no-MM50 0.02232。
- no-MM50 的 HR 0.03370、NDCG 0.01721，相对 MM101 点估计 +7.65%。
- 78,921 行用户、Target 和历史长度四组完全对齐；no-MM50 相对 MM50 +6.20%，相对 no-MM101 +5.08%。
- 整体交互项区间跨 0，单 seed 也不覆盖训练随机性，因此不作稳定因果结论。
- 81+ 历史组占 63.47%，该组 no-MM50 相对 no-MM101 +12.96%；短历史桶赢家不一致。

### 7:00–8:30：工程化工作

- 设备/路径参数化，CPU、CUDA、Ascend 路由。
- 确定性划分、断点恢复、smoke test 和回归测试。
- PyTorch 精确 Top-K，摆脱机器专用 Faiss 二进制依赖。
- SafeTensors 转换，48 个张量逐键验证等价。
- 本地/远端/Hugging Face 清单和 SHA-256 证据链。

### 8:30–9:30：故障处理

- watcher 停滞时只恢复同步，不重复训练。
- 16 路 SCP 部分失败时复用 11 个已验证分片、降低并发、只补 5 片。
- GPU调度策略写入启动器，不抢占共享资源，并在本地校验后及时清理远端。

### 9:30–10:00：反思和下一步

- 最重要的收获是评测契约和 ID 对齐优先于盲目换模型。
- 下一步先用多 seed 验证 81+ 切片和整体差异，再尝试门控多模态、自适应近期窗口和 ANN 延迟/召回权衡。
- 面试结束句：这个项目展示的不只是一个分数，而是从实验设计、实现、统计解释到产物治理的完整推荐系统能力。
